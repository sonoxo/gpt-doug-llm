# ZYRA Intelligence Incident Response Plan

## Command mission
Detect, contain, preserve evidence, recover, and document security incidents affecting ZYRA, GPT-DOUG, GPT-GLASSONION, ontology packages, credentials, build systems, or regulated data.

## Severity
- P1: confirmed compromise, regulated-data exposure, destructive action, integrity failure in locked intelligence, or privileged credential compromise.
- P2: credible intrusion attempt, dependency compromise, material availability loss, or security-control failure.
- P3: contained vulnerability, suspicious event, or low-impact policy deviation.

## Command sequence
1. **IDENTIFY** — establish event time, affected boundary, source, and evidence preservation hold.
2. **CONTAIN** — isolate affected local service/account/environment without retaliatory or third-party action.
3. **PRESERVE** — retain audit logs, hashes, commits, workflow evidence, and relevant configuration snapshots.
4. **ERADICATE** — patch or remove the confirmed cause through controlled change.
5. **RECOVER** — restore from known-good state, re-run security gates, verify ontology/master-lock integrity.
6. **REPORT** — document timeline, impact, decisions, notifications, and corrective actions required by the applicable Virginia/federal data scope.
7. **LEARN** — open POA&M items and regression tests for every confirmed control failure.

## Command constraints
- No counter-hacking, retaliation, unauthorized access, or destructive external action.
- Regulated-data notification timelines are determined by the applicable contract, law, policy, and system authority.
- High-impact attribution remains intelligence analysis until evidence and command review support promotion.
