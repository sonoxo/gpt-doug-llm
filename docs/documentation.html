Design Principles

The ecosystem is built around a few repeatable constraints: ontology before isolated scripts, browser access before unnecessary installation, evidence before status claims, local execution when privileged access is required, and explicit provenance for third-party components.

01

Ontology-first

Objects, links, actions, ownership, dependencies, capabilities and events are modeled as a connected system instead of unrelated repositories.

02

Browser-first / free-access

Interactive creations should expose a free browser page whenever the capability can safely run on the web.

03

Evidence-gated

Tests, CI, runtime checks and explicit truth states are preferred over declaring a component complete without proof.

04

Local where necessary

Filesystem, hardware, private credentials and privileged controls remain local or admin-only instead of being pushed into public browser code.

NXYZ Cloud

NXYZ Cloud is the local compute/service layer used for self-hosted runtime experiments and node-oriented workflows. The local CLI is designed to hide multi-step startup behind a compact command surface.

Agent Runtime

The runtime separates planning/execution from verification and boundaries. GPT‑DOUG is the planning and work-execution identity; Zyra is the guard/verification identity; evidence flows back into the status layer instead of being treated as implicit success.

Ontology

The shared ontology is the connective tissue across agents and repositories. A component should have a canonical identity, purpose, owner, dependencies, capabilities, interfaces, permissions, environments and evidence rather than existing as an isolated project.

Objects

Canonical entities

Agents, repositories, tools, services, Houses, datasets, actions, environments and evidence records.

Links

System relationships

Owns, depends-on, exposes, verifies, deploys-to, consumes, derives-from, monitors and governs.

Actions

Governed operations

Build, test, deploy, ingest, validate, simulate, publish, rollback and audit.

BPO

Build Palantir Ontology

Standing command for ontology-first repository work: object/link types, actions, schemas, ingestion, validation and integration points.

Creation Standard

Interactive creations are expected to receive a free public browser page whenever technically and safely possible, plus a catalog entry in the XUNIA resource hub. Local-only access must be justified by a real technical requirement such as hardware, private credentials or filesystem permissions.
