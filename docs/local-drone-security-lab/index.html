System architecture

Alarm event → Human review → Safety gate
Local perception → Privacy filter → Evidence log
  • Official, supported SDK only; no firmware bypass.
  • On-device inference is a design option, not a performance claim.
  • Geofence and manufacturer failsafe take priority over camera tracking.

Hard safety gates

  • Alarm does not automatically launch an aircraft.
  • Human approval is required for every launch request.
  • No person pursuit, face recognition, or cross-occlusion identity tracking.
  • Never cross an authorized property boundary.
  • Uncertain location, link loss, low battery, or obstacle risk: abort and use documented failsafe.

Before real-world testing

NOT FLIGHT-READY
  • Confirm aircraft model and official SDK support from current manufacturer documentation.
  • Review aviation rules, local ordinances, privacy, and property permissions.
  • Test the state machine and failsafes in simulation/bench conditions first.
  • Do not treat a distance or altitude number as a safety certification.

Evidence contract

Each event should distinguish synthetic from live data, record timestamps and source revisions, restrict access, and expire according to a short retention policy. Prefer event metadata over continuous recording.
